# ADR-0003: k6 for Performance Tests

- **Status:** Accepted
- **Date:** 2026-10-06

## Context
We need to know how many concurrent guards and dashboards SECU can sustain before load grows in production. Selenium documentation explicitly discourages using it for performance testing.

## Decision
Grafana k6.

## Alternatives Considered
| Option | Pros | Cons |
|---|---|---|
| **k6** | Lightweight (thousands of VUs on a laptop); thresholds give pass/fail natively for CI; scripts are readable code | JavaScript (second language in the repo) |
| Gatling | Java DSL (same language) | Heavier setup |
| JMeter | No code; mature | Resource-heavy; XML test plans hard to review |

## Consequences
- CI-friendly performance gate via thresholds.
- Performance scripts live in a separate `performance/` folder with their own tooling.
